PAGE 4: WHY SPRING BOOT 3.x?
Content:
The Evolution: Spring Framework was powerful but required massive XML configurations. Spring Boot changed the game by being Opinionated.
Opinionated means Spring Boot makes a best-guess choice for you. If you add 'spring-boot-starter-web', it assumes you want an embedded Tomcat server and JSON support.

Key Value Props:
1. Auto-Configuration: The @EnableAutoConfiguration magic that configures your app based on the classpath.
2. Starter Dependencies: Aggregated pom.xml entries that pull in all necessary libraries.
3. Embedded Servers: No more deploying WAR files to external Tomcat. The server is inside the JAR.
4. Java 21 Power: Virtual Threads (Project Loom) allow your app to handle millions of concurrent requests without crashing the JVM.
5. Jakarta EE 10: The migration from javax.* to jakarta.* namespaces.

PAGE 8: DEEP DIVE: PACKAGE LAYOUT
Content:
The Layered Architecture (Separation of Concerns):
To prevent your code from becoming a 'big ball of mud', we use specific packages:
1. .controller: The Entry Point. Handles HTTP requests and returns responses. No business logic here!
2. .service: The Brain. Contains all business rules, calculations, and orchestrations.
3. .repository: The Data Access Layer. Interfaces that talk to the database.
4. .model/entity: The Blueprint. Java classes that map to database tables.
5. .dto: Data Transfer Objects. Simple POJOs used to move data between the API and the Service.

PAGE 9: THE ENTRY POINT: @SPRINGBOOTAPPLICATION
Content:
Every app starts with one class annotated with @SpringBootApplication.
Code Example:
```java
package com.dev.springmastery;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class SpringMasteryApplication {
    public static void main(String[] args) {
        SpringApplication.run(SpringMasteryApplication.class, args);
    }
}
```
What is happening under the hood?
@SpringBootApplication is a convenience annotation that combines:
1. @Configuration: Tags the class as a source of bean definitions.
2. @EnableAutoConfiguration: Tells Spring Boot to start adding beans based on classpath settings.
3. @ComponentScan: Tells Spring to look for @Component, @Service, etc., in the current package and sub-packages.

PAGE 10: SPRING TERMINOLOGIES I (THE BASICS)
Content:
1. Bean: An object that is instantiated, assembled, and managed by the Spring IoC container. It is not just a Java object; it is a Spring-managed object.
2. ApplicationContext: The 'Big Box' that holds all the Beans. It is the heart of the Spring Framework.
3. Inversion of Control (IoC): Instead of you saying 'new UserService()', you tell Spring 'I need a UserService' and Spring provides it. Control is inverted from the dev to the framework.
4. Dependency Injection (DI): The act of pushing a dependency into a class (usually via constructor).

Analogy: The Coffee Machine.
You don't build a coffee machine every time you want espresso. You just ask the 'Kitchen' (ApplicationContext) for the 'CoffeeMachine' (Bean), and the Kitchen gives it to you, already plugged in and ready to use.

PAGE 11: SPRING TERMINOLOGIES II (ADVANCED)
Content:
1. Stereotypes: Special annotations that tell Spring what a class does.
   - @Component: General-purpose bean.
   - @Service: Indicates a business logic layer.
   - @Repository: Indicates a data access layer (handles DB exceptions).
   - @Controller: Indicates a web handler.
2. AOP (Aspect Oriented Programming): Separating cross-cutting concerns (like logging or security) from the main business logic.
3. Component Scanning: The process where Spring scans your packages to find classes marked with stereotypes and adds them to the context.

PAGE 12: THE REQUEST-RESPONSE CYCLE
Content:
Workflow of a single API call:
1. Client (Postman/Browser) sends an HTTP Request (e.g., GET /users/1).
2. DispatcherServlet: The front door of Spring. It receives the request and routes it to the correct Controller.
3. Controller: Validates the request and calls the Service.
4. Service: Processes business logic (e.g., checks if user is active). Calls the Repository.
5. Repository: Executes a SQL query via JPA/Hibernate to the Database.
6. Database: Returns the row.
7. Repository -> Service -> Controller: Data flows back up.
8. Controller: Wraps the data in a ResponseEntity and sends the HTTP Response (200 OK).

PAGE 13: BUILDING YOUR FIRST REST CONTROLLER
Content:
The @RestController annotation tells Spring that every method returns data (JSON) instead of a HTML view.

Code Example:
```java
@RestController
@RequestMapping("/api/hello")
public class HelloController {
    
    @GetMapping
    public String sayHello() {
        return "Welcome to Spring Boot 3.x!";
    }
}
```
Breakdown:
- @RequestMapping("/api/hello"): The base path for all methods in this class.
- @GetMapping: Maps HTTP GET requests to this method.

PAGE 14: PATH VARIABLES AND REQUEST PARAMETERS
Content:
How to make APIs dynamic.

1. @PathVariable: Used for resource identification.
Example: GET /users/5 (Where 5 is the ID).
```java
@GetMapping("/users/{id}")
public String getUser(@PathVariable Long id) {
    return "Fetching user with ID: " + id;
}
```

2. @RequestParam: Used for filtering, sorting, or searching.
Example: GET /users?name=john
```java
@GetMapping("/users")
public String searchUser(@RequestParam String name) {
    return "Searching for user: " + name;
}
```

PAGE 15: THE SERVICE LAYER (THE BRAINS)
Content:
Why a Service? If you put logic in the Controller, your code becomes untestable and messy. The Service layer acts as a buffer.

Code Example:
```java
@Service
public class UserService {
    public String processUserLogic(String name) {
        if (name == null) return "Invalid Name";
        return "Processed User: " + name.toUpperCase();
    }
}
```
The Controller then calls this service. This keeps the Controller slim and the logic reusable across different controllers.

PAGE 16: DEPENDENCY INJECTION IN ACTION
Content:
How to connect a Controller to a Service.

Avoid Field Injection (@Autowired on the field) because it makes unit testing hard.
Use Constructor Injection (The Gold Standard).

Code Example:
```java
@RestController
public class UserController {
    private final UserService userService;

    // Spring automatically injects UserService here
    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/process")
    public String process(@RequestParam String name) {
        return userService.processUserLogic(name);
    }
}
```
Why is this based? Immutability (final field) and easy Mocking in JUnit tests.

PAGE 17: MODEL VS DTO
Content:
Entities are your DB tables. DTOs (Data Transfer Objects) are your API contracts.
NEVER return an @Entity directly to the user. Why?
1. Security: You might accidentally leak the 'password' field of a User entity.
2. Coupling: If you change your DB column name, your API breaks for all your users.

Flow:
DB -> Entity -> Service (Maps Entity to DTO) -> DTO -> Controller -> Client.

PAGE 18: INTRODUCING SPRING DATA JPA
Content:
JPA (Java Persistence API) is a specification. Hibernate is the implementation. Spring Data JPA is a wrapper that makes it incredibly easy.

Instead of writing complex SQL, you create an interface that extends JpaRepository.

Configuration (application.properties):
spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.driverClassName=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=password
spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
spring.h2.console.enabled=true

PAGE 19: DATABASE CONNECTION LOGIC
Content:
The Plumbing Flow:
Spring Boot Application -> DataSource (HikariCP) -> Hibernate (ORM) -> JDBC -> Database.

Key Concept: HikariCP.
Spring Boot uses HikariCP as the default connection pool. Instead of opening/closing a connection for every request (which is slow), it keeps a pool of warm connections ready to be used.

H2 vs PostgreSQL:
- H2: In-memory, disappears on restart. Great for learning.
- PostgreSQL: Persistent, production-ready. Requires installation and a different driver.

PAGE 20: CREATING YOUR FIRST ENTITY
Content:
An Entity is a Java class that represents a table.

Code Example:
```java
@Entity
@Data // Lombok: adds getters/setters
@NoArgsConstructor
@AllArgsConstructor
public class Task {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(nullable = false)
    private String title;
    
    private boolean completed;
}
```
Annotations:
- @Entity: Marks it as a JPA entity.
- @Id: Defines the primary key.
- @GeneratedValue: Auto-increments the ID.

PAGE 21: THE REPOSITORY LAYER (CRUD MAGIC)
Content:
The power of JpaRepository. You don't write implementation code; Spring generates it.

Code Example:
```java
@Repository
public interface TaskRepository extends JpaRepository<Task, Long> {
    // Custom query method: Spring parses the name to generate the SQL!
    List<Task> findByCompleted(boolean completed);
}
```
Built-in methods you get for free:
- save(entity): Create or Update.
- findAll(): Get all rows.
- findById(id): Get one row.
- deleteById(id): Remove a row.

PAGE 22: CONNECTING THE DOTS: FULL CRUD FLOW
Content:
Putting it all together.
Controller -> calls Service -> calls Repository -> hits DB.

Full Flow Example:
1. Controller: @PostMapping('/tasks') -> calls service.createTask(dto)
2. Service: converts dto to Entity -> calls repository.save(entity)

PAGE 23: EXCEPTION HANDLING
Content:
Stop returning 500 Internal Server Error. Use a Global Exception Handler.

Code Example:
```java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<String> handleNotFound(ResourceNotFoundException ex) {
        return new ResponseEntity<>(ex.getMessage(), HttpStatus.NOT_FOUND);
    }
}
```
Custom Exception:
```java
public class ResourceNotFoundException extends RuntimeException {
    public ResourceNotFoundException(String message) { super(message); }
}
```

PAGE 24: VALIDATION
Content:
Ensure bad data never hits your DB.
Dependency: spring-boot-starter-validation.

Code Example in Entity/DTO:
```java
public class TaskRequest {
    @NotNull(message = "Title cannot be null")
    @Size(min = 3, max = 100, message = "Title must be between 3 and 100 chars")
    private String title;
}
```
In Controller:
```java
@PostMapping("/tasks")
public ResponseEntity<Task> create(@Valid @RequestBody TaskRequest request) {
    // ...
}
```
@Valid triggers the check. If it fails, Spring throws MethodArgumentNotValidException.

PAGE 25: APPLICATION CONFIGURATION
Content:
application.properties vs application.yml.
YAML is more readable for nested structures.

Profiles:
You can have different configs for different environments:
- application-dev.properties (H2 DB)
- application-prod.properties (PostgreSQL DB)
Run using: spring.profiles.active=dev

@Value:
Inject a value from the properties file into your code.
@Value("${app.welcome.message}")
private String welcomeMsg;

PAGE 26: LOGGING AND MONITORING
Content:
Stop using System.out.println(). Use SLF4J.

Code Example:
```java
@RestController
public class LogController {
    private static final Logger logger = LoggerFactory.getLogger(LogController.class);
    
    @GetMapping("/log")
    public String testLog() {
        logger.info("This is an INFO log");
        logger.error("This is an ERROR log");
        return "Logged!";
    }
}
```
Spring Boot Actuator:
Add dependency: spring-boot-starter-actuator.
Enable endpoints in properties: management.endpoints.web.exposure.include=*
Visit /actuator/health to see if your app is alive.
